# 视觉历史缩减的成本与部署评估方案

2026-10-01。用户提出扩大“降本”评估，本文件将评估口径具体化。状态为方案，尚未执行新成本benchmark、缓存适配、故障干预或新训练，不改变冻结四组或当前控制器。

## 核心目标与判据

研究主线仍为相机—雷达未来3D语义占据：SDK速度是否减少所需视觉历史。成本作为该主张的配套证据，不能取代精度/历史交互检验。四组第10轮5119主比较及预先确定的−0.3pp非劣界不变，best仅辅助。最终同时展示精度—延迟、精度—内存与精度—能耗，说明优势发生在哪种运行方式，不用单一“mIoU/FLOPs”比值掩盖精度损失。

## 需要测量的维度

| 维度 | 主要指标 | 比较回答的问题 |
|---|---|---|
| 推理计算/延迟 | BS1端到端P50/P95毫秒、持续吞吐；拆读图解码、传输、backbone、雷达、八槽复制/采样、占据解码 | 少历史是否降低实际等待与算力需求 |
| 运行内存 | GPU peak allocated/reserved、独占进程显存、CPU RSS/PSS、长期特征缓存字节及条目 | 能否降低设备容量与历史状态维护需求 |
| 历史/I-O需求 | 唯一视觉观测数、实际历史跨度秒、唯一文件读取与逻辑字节、解码图数、H2D字节、cache命中率 | 减少了哪些输入和搬运；随机访问与顺序复用分别是多少 |
| 启动/恢复 | 空历史/场景切换后的首个有效输出延迟、达到预定精度所需历史跨度及anchor数 | 模型能否更早提供可靠预测；不把预填历史的离线首帧当真实启动 |
| 能耗 | GPU J/完整未来预测，整段GPU总能耗；可选独立整机电表 | 延迟改善是否伴随能耗下降；平均瓦数本身不足以回答 |
| 训练/蒸馏总成本 | 固定10轮GPU小时、每步/峰值显存；初始化/验证/失败恢复单列；未来KD教师计算和缓存费用 | 推理节省是否以额外训练成本换取 |

“完整未来预测”始终包含同一当前及1/2/3秒输出，不能通过少预测一个时域或降低分辨率节省成本。六个相机仍然保留；H1缩短时间历史，不减少摄像头个数。

## 当前实现的限制已由源码核对

`models/sparse_world.py`第59–74行用feature.repeat物理复制当前特征至八槽。因此H1减少backbone唯一图像数，但八槽特征张量、采样和预测接口仍保留。参数量不随历史输入缩减，不能宣称模型权重压缩或总体8倍显存/计算下降。

第352–358行在visual_history_frames显式为1/8时绕过legacy缓存，进入完整输入的offline路径。第388–398行默认None模式才使用历史特征memory/queue。四组现有验证速度不能代表带缓存部署的稳态速度。已有stage=train遥测混合优化、验证和等待，不能当独立推理成本；原H1成本记录也明确不提供精确能耗。

## 分三种运行条件报告

1. **独立anchor、模型常驻、历史特征缓存为空**：现有冻结H1/H8实际路径，分别加载6/48图。模型加载/首次CUDA初始化额外列示，不混入常驻模型延迟；文件系统缓存状态另记录，不将“清模型历史缓存”称为“清磁盘缓存”。这一条件可评估离线重算节省。
2. **连续场景、现有冻结路径**：按真实时间顺序重放，测目前实现实际延迟、输入复用和内存。显式H8仍重算，标注“无特征缓存”，不能冒充最佳在线基线。
3. **连续场景、因果特征缓存**：需要独立测量适配器，H8按真实图像身份缓存且不重新编码已存在特征；H1也允许合理的当前特征复用。必须先核验输入/增强/精度模式、原始输出及最终占据与同一checkpoint参考一致，容差沿用已授权评估规则；不能简单把visual_history_frames设None切换到具有不同数值路径的legacy函数。缓存需要的额外历史帧按真实序列计入，不假设每步恒定六张新图。当前没有已实现/通过准入的该适配器，这一结果尚缺。

原生1/2槽模型属于另一个实现变化；若下一阶段做，需独立版本和匹配基线，不将其成本收益算作当前八槽H1已实现收益。少加载历史也不意味着持续摄像头采集带宽、完整训练数据存储直接下降8倍：稳态同一摄像头新帧可能只被编码一次，数据集中图像也可能为其他anchor复用。

## 可执行测量约定

- 优先使用四组已有epoch10冻结checkpoint，BS1，H200同一卡型号、相同输入分辨率/六视角/雷达点集/精度模式/未来输出与查询预算。无需重新训练；best另作辅助，不以benchmark选模。
- 冻结一份按场景配对的真实评估序列manifest，包含tokens、图像身份、时间戳、模型与源码hash。覆盖不同历史跨度与雷达点数；同一场景内保留连续顺序。明确N和覆盖场景数，不只反复测一个预加载tensor。
- 每种配置先预热30次（完成CUDA/模型预热，不替代真实历史积累），正式3次场景重放，顺序交替并记录时钟/功率限制/温度。模型计时在GPU同步后取边界，端到端同时记录实际CPU解码/搬运与占据输出完成；profiler另开，不把profiling开销混入主测量。
- 吞吐和单请求尾延迟分开测。FLOPs/MACs只作辅助；自定义CUDA采样算子未覆盖时列出缺项，不按0计入总量。allocated、reserved、进程占用三种显存分别报告，实际峰值与30秒遥测采样峰值不能混用。
- GPU独占、原卡锁/资源准入，待原训练评估队列完成或真正空闲时进行，不抢占现有任务。多重复block只刻画系统测量波动，不能替代训练多种子。
- 能耗优先使用支持的NVML累计能量计数器前后差（mJ转J），按完整有效输出数归一。若不支持，功率积分作为估计，记录采样率和不确定性；当前30秒混合遥测不可据此补造精确能耗。GPU能耗不包含相机/雷达/CPU/存储或冷却耗电，不能称整车总能耗。
- 对H1v/H8v先量化“同样已有雷达、缩短历史”的边际成本。若对纯相机声称总成本优势，需要同输入/预算的相机对照及雷达新增分支/设备成本；不能将雷达免费计算，也不自动新增训练臂。

## 可靠性与额外训练代价

历史缺失、延迟、时间不同步、场景切换后的性能是历史依赖的补充测试，应同时报告精度恢复曲线与启动成本。若重放只丢历史、保持当前图像和雷达相同，结论限于该故障设定，不能替代当前摄像头失效、长遮挡或所有信息条件的鲁棒性。精度阈值沿用原非劣界；无法满足时如实报告，不能为达标改门槛。

未来KD把教师训练/已有教师复用、教师推理、特征缓存生成和学生训练分别入账。一次性训练成本与每次推理节省的break-even可在同一能量或货币单位下计算，不能用GPU小时直接减毫秒或J。当前失败恢复是campaign已发生成本，复现方法成本与这次实际campaign成本并列，嵌套阶段不重复加。

## 最终交付

主结果表保留H1/H8×velocity/geometry四组全量精度，同时附离线P50/P95、GPU峰值、历史跨度和GPU训练小时。已验证的缓存重放另表列出稳态P50/P95、真实cache字节/命中率及J/预测；未测列空并标待测。启动/恢复曲线为补充图。论文能够主张的是达到预设精度条件时减少哪一种实测资源；少帧本身不是完整降本结论。

测量依据：[PyTorch benchmark预热与异步同步](https://docs.pytorch.org/docs/2.14/benchmark_utils.html)、[NVIDIA累计GPU能量接口](https://nvidia.github.io/cuda-python/cuda-bindings/13.3.2/module/generated/cuda.bindings.nvml.device_get_total_energy_consumption.html)。文档说明测量方式，不证明本项目已取得节省。
