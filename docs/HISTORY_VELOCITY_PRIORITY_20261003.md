# 速度模型主线优先，几何对照暂缓

2026-10-03，用户明确要求：“你先做更有用的主线，几何对照先别管，之后补做都行。”本页覆盖此前要求等待四臂完成才推进速度比较与成本测量的调度限制。现阶段交付目标是修正版本H2速度对H8速度的精度与实测成本；H8几何重新准入、训练及相关诊断暂缓，原失败证据保留，已经完成的H2几何也不重做。

H8速度已经完成十轮、final/best全5119和原固定256干预。H2速度继续原独立正式训练与收尾，不迁移或重启活trainer。两者科学仍固定`0f33492d1b639da716897d8faa4a1df293354c49`，完整官方模型加雷达、新优化器起点、单种子0、BS8、十轮29920迭代、数据及损失预算保持。这里没有追加H4、KD或新模块训练。

GPU1独立承担成本测量。先对已完成的H8速度做一个单模型预备测量块；此时另一张卡仍可能训练，因此该块的系统上下文与耗时单列，排除最终配对成本。待H2速度的完整result、checkpoint审计、全评和干预全部落盘后，用同一GPU1、同一256真实输入/16连续场景、BS1、30预热及三次交替重放测两组。顺序为H8→H2、H2→H8、H8→H2，正式配对块要求两卡无其他compute。每块持原GPU1锁与原共享全评锁，空闲132000MiB和主机64GiB持续60秒；等待时不占GPU显存，不停止他人任务。

新增测量工具与调度器置于独立快照；原科学快照全部文件SHA保持。原特征缓存适配、预热、三种测量路径和原始输出容差保持；每块缓存需16真实输入全部13张量及最终体素通过。失败冻结原始诊断并排除该缓存路径，离线测量仍可完成。新增审计读取实际图像张量shape/dtype/storage字节，替代只由分辨率推算的未注明dtype字节数。P50/P95、内存、逻辑文件字节、历史跨度与支持时GPU累计能量按原定义记录；CPU仍加载完整输入，不声称优化历史I/O、最佳在线部署、全5119缓存精度或整机能耗。

两速度臂完整后，使用final10全5119/150同场景、2000次配对bootstrap，检验原H2v−H8v非劣界−0.3个百分点；best仅辅助。未补齐H8几何时不计算四臂交互，也不声称速度导致历史需求下降。结论限于已测2与8帧、固定模型/单种子及复用验证集。

原GPU0控制器在H2速度收尾后仍会等待四臂旧条件；此等待不代表速度主线未完成或需要重训。后续实时核验无活子进程后再处理旧等待调度器，不能提前中断H2训练、全评或干预。独立速度队列及最终中文公开报告完成后，再按实际剩余工作决定心跳结束；暂缓几何不再阻挡当前速度主线交付。
