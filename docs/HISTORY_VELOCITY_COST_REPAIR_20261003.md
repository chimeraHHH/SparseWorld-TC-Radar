# H8速度成本适配修复

用户要求修复H8速度成本测量。原预备块在首个真实输入的缓存一致性门禁被拒绝：13个输出中12个超过原容差，四个时域的原生占据体素均不精确。原冻结张量、日志和收据保留，原预备块仍排除最终配对成本。

源码核查发现原成本缓存适配把H8原来的48图像FP16提取拆成6图像调用，并按文件名合并重复历史槽。这改变了提取的数值计算形状。新的独立适配在任何未命中时调用完整原提取器；只有完整图像批次和槽位均命中时才复用特征，使用当前输入的投影，不缓存相机位姿。H2使用原有真实历史特征复制函数。此修复不改科学版本、权重、训练预算、输入历史或原输出容差。

新零优化诊断固定原H8第10轮权重和预备块首输入，对比原48图像提取、原6图像缓存、修复后的冷缓存和纯缓存命中。四种特征、13个预测张量和四时域原生体素完整冻结，记录文件SHA和实际提取批次。GPU证据落盘之前，源码差异只作为待验证的原因；通过诊断也不能代表精度或加速收益。

测量仍要求16个真实输入的全部13输出满足原atol=1e-4、rtol=1e-5，四时域占据坐标和类别精确；新增同输入纯命中验证，确认没有再次图像提取。三次配对重放、两个速度臂共六块全部通过才允许缓存比较，否则双方所有缓存计时均从配对结果中排除并单列诊断。不拼接通过的缓存块。

保留完整批次计算可能没有缓存加速：不同锚点改变任何图像都会完整重算，仍然加载全部CPU图像输入。报告会给出真实重算和纯复用计数，不把可运行当收益，不称在线最优或历史I/O优化。16输入一致性也不代表5119缓存精度验证。预备块与GPU0训练并行，仍不进入最终成本比较；正式六块等待H2速度完整收尾和两卡无其他compute，再按原锁和连续60秒资源门禁运行。
